# Tooltip System for ScreenerTab + ChartingTab

## Goal
Add hover tooltips to every data label/header in ScreenerTab and ChartingTab so any layman understands what each number means and where it comes from.

## Approach
Install `@radix-ui/react-tooltip`, create a reusable `InfoTooltip` component, a centralized tooltip content map, and wire it into the two tabs.

---

## Step 1 — Install dependency

```bash
npm install @radix-ui/react-tooltip
```

**File:** `frontend/package.json` (auto-modified by npm)

---

## Step 2 — Create tooltip content data file

**New file:** `frontend/src/data/tooltipContent.ts`

Single source of truth for all tooltip text. TypeScript record keyed by string, each entry has `{ text: string; source: string }`.

Organized by section:
- `screener.*` — ScreenerTab table column headers (15 entries)
- `sig.*` — Expanded row: Technical Signals (14 entries)
- `research.*` — Expanded row: Research Factors (12 entries)
- `metrics.*` — Expanded row: Key Metrics (10 entries)
- `footer.*` — Expanded row footer bar items (3 entries)
- `chart.sidebar.*` — ChartingTab sidebar panel labels (~35 entries)
- `chart.panel.*` — ChartingTab panel titles + chart legend items (~10 entries)
- `chart.peer.*` — ChartingTab peer comparison table headers (8 entries)

~100 total entries. Each is 1-2 sentences of layman explanation + source attribution.

## Step 3 — Create `InfoTooltip` component

**File:** `frontend/src/components/shared.tsx` (append to existing)

```tsx
import * as Tooltip from '@radix-ui/react-tooltip'
import { Question } from '@phosphor-icons/react'
import { tooltips, type TooltipEntry } from '../data/tooltipContent'

export function InfoTooltip({ id, children }: { id: string; children?: React.ReactNode }) {
  const entry = tooltips[id]
  if (!entry) return children ? <>{children}</> : null
  return (
    <Tooltip.Provider delayDuration={200}>
      <Tooltip.Root>
        <Tooltip.Trigger asChild>
          {children ? (
            <span className="inline-flex items-center gap-1 cursor-help">{children}</span>
          ) : (
            <span className="inline-flex items-center gap-1 cursor-help">
              <Question size={11} weight="light" style={{ color: 'var(--text-3)', opacity: 0.6 }} />
            </span>
          )}
        </Tooltip.Trigger>
        <Tooltip.Portal>
          <Tooltip.Content
            className="tooltip-content"
            sideOffset={6}
            side="top"
            style={{
              background: 'var(--glass-bg-strong)',
              backdropFilter: 'blur(var(--glass-blur))',
              WebkitBackdropFilter: 'blur(var(--glass-blur))',
              border: '1px solid var(--glass-border-strong)',
              borderRadius: 'var(--radius)',
              boxShadow: 'var(--glass-shadow-lg)',
              padding: '8px 12px',
              maxWidth: 280,
              zIndex: 9999,
            }}
          >
            <p style={{ fontSize: 11, lineHeight: 1.5, color: 'var(--text)', margin: 0 }}>
              {entry.text}
            </p>
            <p style={{ fontSize: 10, color: 'var(--text-3)', margin: '4px 0 0', fontStyle: 'italic' }}>
              Source: {entry.source}
            </p>
            <Tooltip.Arrow style={{ fill: 'var(--glass-bg-strong)' }} />
          </Tooltip.Content>
        </Tooltip.Portal>
      </Tooltip.Root>
    </Tooltip.Provider>
  )
}
```

Also wrap the entire app in `<Tooltip.Provider>` at the root — **one line in `App.tsx`** around the rendered content (or just rely on per-component providers as shown above to avoid touching App.tsx).

**Decision:** Use per-component `<Tooltip.Provider>` inside `InfoTooltip` itself (shown above) so we don't need to modify App.tsx at all. This is slightly less efficient but avoids touching the 734-line App.tsx for a single wrapper.
