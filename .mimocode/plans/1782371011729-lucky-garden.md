# Plan: Login System, README Update & .venv Setup

## 1. SEBI Regulations Summary

**Key finding: The dashboard's public display of buy/sell recommendations, conviction ratings, and composite scores likely violates SEBI regulations without registration.**

### Relevant Regulations:

| Regulation | Scope | Impact on Alpha |
|---|---|---|
| **SEBI (Investment Advisers) Regulations, 2013** (last amended Nov 2025) | Anyone giving "investment advice" (buy/hold/sell recommendations) for consideration must register as IA | Conviction ratings ("Strong Buy", "Avoid") = investment advice |
| **SEBI (Research Analysts) Regulations, 2014** (last amended Nov 2025) | Anyone publishing research reports with buy/sell recommendations must register as RA | Composite scores + top picks = research report |
| **SEBI Master Circular for IAs (Jun 2025)** | Consolidated operational guidelines | Defines scope of "investment advice" broadly |
| **SEBI finfluencer crackdowns (2024-2025)** | Multiple enforcement orders against unregistered entities giving stock tips publicly | SEBI actively pursuing enforcement |

### What Counts as "Investment Advice":
- Buy/Hold/Sell recommendations
- Conviction ratings (Strong Buy, Buy, Hold, Caution, Avoid)
- Composite scores presented as actionable signals
- "Top picks" / "Top 3 stocks"

### What's Safe to Show Publicly:
- Raw market data (prices, OHLCV)
- Technical indicators (RSI, MACD, etc.) as educational data
- Screened stock lists without buy/sell labels
- Historical data and charts
- Educational/explanatory content

### Recommended Approach:
Restrict access to recommendation-generating features behind login. This makes it a **restricted-access research platform** (like an internal club tool), not a public investment advisory service. The login requirement creates a controlled audience, which is a key factor in SEBI's enforcement decisions.

### 2.1 Login System (Frontend-Only, localStorage-based)

**Why frontend-only:** There's no Python backend server. The app is a static site deployed on Vercel. A simple client-side auth is sufficient for SEBI compliance (restricted access), since this is a club tool, not a commercial platform.

**Credentials:** `email: alpha@fms.edu`, `password: alphakishakti`

**Auth state:** Stored in `localStorage` as `qa_auth` (similar pattern to `qa_dark` for theme).

### 2.2 Changes to `frontend/src/App.tsx`

1. **Add auth state:**
   ```tsx
   const [isLoggedIn, setIsLoggedIn] = useState(() => {
     try { return localStorage.getItem('qa_auth') === 'true' } catch {}
     return false
   })
   ```

2. **Add login button** next to Dark/Light toggle (in both dark and light header branches):
   - Same styling as the theme toggle button
   - Icon: `SignIn` from `@phosphor-icons/react`
   - Label: "Login" (when logged out) / "Logout" (when logged in)
   - Clicking "Login" shows an inline dropdown/popover with email + password fields
   - Clicking "Logout" clears `qa_auth` from localStorage

3. **Filter TABS array** based on auth state:
   ```tsx
   const ALL_TABS = [
     { id: 'picks', label: 'Signals', icon: TrendUp },
     { id: 'fundamentals', label: 'Screen', icon: Database },
     { id: 'charting', label: 'Charts', icon: ChartBar },
     { id: 'heatmap', label: 'Heatmap', icon: StackSimple },
     { id: 'factorlab', label: 'Factor Lab', icon: Pulse },
   ] as const

   const TABS = isLoggedIn ? ALL_TABS : ALL_TABS.filter(t =>
     t.id === 'fundamentals' || t.id === 'charting' || t.id === 'heatmap'
   )
   ```
   - **Visible to all:** Screen, Charts, Heatmap (raw data, no recommendations)
   - **Hidden for non-logged-in:** Signals (top picks with conviction), Factor Lab (model outcome tracking)

4. **Protect recommendation data in Screen tab:**
   - The ScreenerTab shows composite scores and conviction ratings per stock
   - For non-logged-in users: hide Composite_Score, conviction columns, and buy/sell signal badges
   - This is done by passing `isLoggedIn` as a prop to `ScreenerTab`

5. **Auto-redirect on logout:**
   - If user is on a restricted tab (picks/factorlab) and logs out, redirect to `fundamentals`

### 2.3 Login Popover Component

A small inline popover (not a full page/modal) that appears when clicking the Login button:
- Position: below the login button in the header
- Glassmorphism styling (matches existing design system)
- Fields: email, password (styled like existing inputs)
- Submit button
- Error message for wrong credentials
- Closes on successful login or clicking outside
